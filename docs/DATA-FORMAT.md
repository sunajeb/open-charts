# Data format reference

Every open-charts chart is described by a small JSON document, the **chart spec**. The editor, the
PowerPoint add-in and the command line all read and write the same format, and every chart in a
deck carries its spec inside the `.pptx` (see [How charts stay editable](#how-charts-stay-editable)).

This page is generated by hand from `src/core/types.ts`, `src/core/spec.ts` (the validator) and
`schema/*.schema.json`. Every JSON example below is checked by `test/docs.test.ts`, so they are
valid specs. Machine-readable schemas: `schema/chart.schema.json` and `schema/deck.schema.json`.

## Deck

A deck is what the command line reads: a list of slides, each with an optional title and one chart
(or several, see [Several charts on a slide](#several-charts-on-a-slide)).

| Key | Type | Required | Meaning |
|---|---|---|---|
| `slides` | array | yes | One entry per slide: `{ "title"?: string, "chart": <chart spec> }`, or `{ "title"?: string, "charts": [{ "frame"?: {x, y, w, h}, "chart": <chart spec> }] }`. |
| `style` | object | no | Fonts and colours for every chart in the deck. See [Style](#style). |
| `specVersion` | `1` | no | Format version. Leave it out or set it to `1`. |
| `$schema` | string | no | Ignored; lets editors find the JSON Schema. |

```json
{
  "slides": [
    {
      "title": "Revenue doubled in three years",
      "chart": {
        "type": "stacked",
        "categories": ["2021", "2022", "2023", "2024"],
        "series": [
          { "name": "Enterprise", "values": [42, 58, 75, 96] },
          { "name": "SMB", "values": [18, 21, 22, 26] }
        ],
        "options": { "unit": "m", "cagr": { "from": 0, "to": 3 } }
      }
    }
  ]
}
```

The command line also accepts a file that holds a single chart spec (no `slides`); it becomes a
one-slide deck without a title.

### Several charts on a slide

A slide with `charts` instead of `chart` holds several charts. Each entry is `{ "frame"?, "chart" }`;
`frame` is `{x, y, w, h}` in points from the slide's top-left corner (the slide is 960 × 540). Charts
without a frame share the chart area below the title side by side, in equal columns 24 pt apart. A
slide has either `chart` or `charts`, never both. Give the charts the same
[`scaleGroup`](#scalegroup) to draw them at one scale:

```json
{
  "slides": [
    {
      "title": "Price and volume explain the whole gap",
      "charts": [
        {
          "chart": {
            "type": "stacked",
            "categories": ["2022", "2023", "2024"],
            "series": [
              { "name": "Core", "values": [20, 30, 47] },
              { "name": "New", "values": [5, 6, 8] }
            ],
            "options": { "scaleGroup": "revenue", "unit": "m" }
          }
        },
        {
          "chart": {
            "type": "waterfall",
            "categories": ["2023", "Price", "Volume", "2024"],
            "series": [{ "name": "Change", "values": [36, 9, 10, "e"] }],
            "options": { "scaleGroup": "revenue", "unit": "m" }
          }
        }
      ]
    }
  ]
}
```

`open-charts import` gives such a slide back as `charts`, with each chart's frame.

## Chart

| Key | Type | Required | Meaning |
|---|---|---|---|
| `type` | string | yes | One of the 17 chart types below. |
| `categories` | array of strings | yes, at least one | The columns of the datasheet: x-axis labels, slices, activities, points. |
| `series` | array | yes, at least one | The rows of the datasheet. See [Series and cells](#series-and-cells). |
| `options` | object | no | See [Options](#options). |
| `specVersion` | `1` | no | Format version. Specs without it are read as version 1. A higher number is rejected ("made with a newer open-charts?"). |
| `$schema` | string | no | Ignored. |
| `style` | object | no | Style for this chart only, over the deck's. See [Style](#style). |

Unknown keys are errors, everywhere in the spec, so a typo such as `"vlaues"` is reported rather
than silently ignored.

### Chart types

| `type` | Chart | Rows (series) | Columns (categories) | Cell |
|---|---|---|---|---|
| `stacked` | Stacked column / bar | Segments | Columns | number |
| `clustered` | Clustered column / bar | Bars side by side | Groups | number |
| `percent` | 100% column / bar | Segments | Columns, each scaled to 100% | number |
| `waterfall` | Waterfall (bridge) | Deltas (usually one row) | Steps | number, or `"e"` for a computed total |
| `combo` | Columns plus lines | Series; `as: "line"` makes a row a line | Columns | number |
| `line` | Line | Lines | Points | number |
| `area` | Stacked area | Bands | Points | number |
| `area100` | 100% area | Bands | Points, each scaled to 100% | number |
| `mekko` | Mekko (Marimekko) | Segments | Columns; width = column total | number |
| `mekkoxy` | Mekko XY / cost curve | First row: column widths; further rows: stacked heights | Columns | number |
| `scatter` | Scatter | Groups (colour, legend) | Points (the category is the point's label) | `[x, y]` |
| `bubble` | Bubble | Groups | Bubbles | `[x, y, size]` |
| `pie` | Pie | Only the first row is drawn | Slices | number |
| `doughnut` | Doughnut | Only the first row is drawn | Segments | number |
| `harvey` | Harvey balls | Items (one row of balls each) | Criteria | 0–4 quarters, or 0–1 |
| `table` | Table | Table rows | Table columns | number or text |
| `gantt` | Gantt (timeline) | Row 1: Start; row 2: End; further rows: milestone kinds | Activities | date |

## Series and cells

| Key | Type | Required | Meaning |
|---|---|---|---|
| `name` | string | yes | Series name. Must be unique within the chart. |
| `values` | array | yes | One cell per category, so `values` has exactly as many entries as `categories`. |
| `color` | string | no | Hex colour, `"1F3A5F"` or `"#1F3A5F"`. Otherwise the palette colour for the row. |
| `as` | `"column"` or `"line"` | no | Combination chart only: `"line"` draws this series as a line with markers over the columns. |

A cell is one of:

- **a number**, or **`null`** for an empty cell (nothing drawn, no label);
- **`"e"`** in a waterfall: this category is a total, computed from the running sum;
- **`[x, y]`** in a scatter chart, **`[x, y, size]`** in a bubble chart (size must not be negative);
- **a date string** in a Gantt chart (`"2026-03-15"`, `"Mar 2026"`, `"Q2 2026"`; see [Dates](#dates));
- **any text** in a table, shown as typed.

Numbers must be finite. Mekko XY widths (its first series) must not be negative.

### Waterfall

Every value is a change from the running sum: positive values step up, negative values step down.
Total columns stand on the baseline at the running sum. Which categories are totals:

1. `options.totalsAt`, if given;
2. otherwise the first category plus every category with an `"e"` cell, if there are any;
3. otherwise the first and the last category.

A total at the first category is the start value: its values seed the running sum. Values in any
later total are ignored (use `"e"` or `null`). With several series, the positive values of a step
stack upwards and the negative ones downwards.

```json
{
  "type": "waterfall",
  "categories": ["EBITDA 2024", "Volume", "Price", "Costs", "EBITDA 2025"],
  "series": [{ "name": "EBITDA", "values": [100, 18, 9, -27, "e"] }],
  "options": { "unit": "m" }
}
```

### Scatter and bubble

Each category is one point, labelled with the category name. Each series is a group with its own
colour. A point belongs to the series whose cell holds it; leave the other series' cells `null`.
Bubble area is proportional to size.

```json
{
  "type": "bubble",
  "categories": ["Payments", "Lending", "Wealth"],
  "series": [{ "name": "Businesses", "values": [[12, 1.8, 420], [4, 0.6, 180], [9, 1.1, 260]] }],
  "options": { "axisTitles": { "x": "Market growth (%)", "y": "Relative market share (x)" }, "sizeLegend": "Revenue ($m)" }
}
```

### Gantt

Categories are the activities (rows of the chart). The first series holds start dates, the second
end dates; each activity needs both or neither, and the end must come after the start. Every further
series is a kind of milestone (drawn as a diamond with its date). A date means the beginning of that
day, so a bar ending `"2026-03-16"` includes the 15th.

```json
{
  "type": "gantt",
  "categories": ["Diagnostic", "Design", "Steering committee", "Roll-out"],
  "series": [
    { "name": "Start", "values": ["2026-01-05", "2026-02-02", null, "2026-05-04"] },
    { "name": "End", "values": ["2026-02-02", "2026-05-04", null, "2026-11-30"] },
    { "name": "Milestone", "values": [null, "2026-05-04", "2026-03-16", null] }
  ],
  "options": { "today": "2026-04-13" }
}
```

### Mekko XY

The first series is the column widths (for a cost curve, capacity); every further series is a
stacked height. It needs at least two series.

```json
{
  "type": "mekkoxy",
  "categories": ["Mine A", "Mine B", "Mine C"],
  "series": [
    { "name": "Capacity (Mt)", "values": [30, 20, 15] },
    { "name": "Cash cost", "values": [42, 55, 71] }
  ],
  "options": { "sort": "ascending", "unit": { "text": "$", "position": "prefix" } }
}
```

### Harvey balls and tables

Harvey values are quarters from 0 to 4. If every value lies between 0 and 1 and at least one is a
fraction, they are read as completion from 0 to 1. Values outside the range are clamped and
reported. A table shows numbers formatted with the chart's number options and text cells as typed.

```json
{
  "type": "table",
  "categories": ["2023", "2024", "Change"],
  "series": [
    { "name": "Revenue ($m)", "values": [1561.9, 1702.4, "+9%"] },
    { "name": "Headcount", "values": [3510, 3620, "+110"] }
  ]
}
```

## Options

All options are optional. Each option is read by the chart types in the table below; on any other
type the validator rejects it (`/options/cagr: not used by pie charts (only stacked, percent)`).
Older specs without `specVersion` still open: `migrate()` removes such options and reports each one
as a warning. The defaults are what the engine draws when an option is left out (the editor shows the
same values). This table is generated from `src/core/spec.ts` (`OPTIONS`, `optionDefaults`); run
`node --experimental-strip-types --no-warnings scripts/options-table.ts` to print it.

| Option | Value | Chart types | Default |
|---|---|---|---|
| [`unit`](#unit) | string or `{text, position, space}` | all except harvey, gantt | none |
| [`decimals`](#decimals) | whole number 0–10 | all except harvey, gantt | inferred from the data |
| [`format`](#format) | Excel number format | all except harvey, gantt | none |
| [`locale`](#locale) | `en-US` `en-GB` `en-IN` `de-DE` `fr-FR` | all except harvey | `en-US` |
| [`scale`](#scale) | `none` `auto` `k` `m` `bn` | all except harvey, gantt | `none` |
| [`orientation`](#orientation) | `vertical` `horizontal` | stacked, clustered, percent | `vertical` |
| [`valueAxis`](#valueaxis) | boolean | stacked, clustered, percent, waterfall, mekko, line, area, area100, combo, mekkoxy | on for line; off otherwise |
| [`zeroBased`](#zerobased) | boolean | line, scatter, bubble | on, unless the data sits in a narrow band far from zero |
| [`gap`](#gap) | number 0–10 | stacked, clustered, percent, waterfall, combo | `0.5` |
| [`seriesLabels`](#serieslabels) | `right` `legend` `none` | all except harvey, table | chosen per type and data |
| [`totals`](#totals) | boolean | stacked, percent, mekko, area, doughnut, combo, mekkoxy | on for stacked, mekko, mekkoxy; off otherwise |
| [`cagr`](#cagr) | `{from, to, years?}` or `null` | stacked, percent | none |
| [`difference`](#difference) | `{from, to}` or `null` | stacked, percent | none |
| [`totalsAt`](#totalsat) | array of category indices | waterfall | the first category and the `"e"` cells, else first and last |
| [`step`](#step) | boolean | line | off |
| [`percentData`](#percentdata) | boolean | percent | off |
| [`combo`](#combo) | `stacked` `clustered` | combo | `stacked` |
| [`mekko`](#mekko) | `percent` `unit` | mekko | `percent` |
| [`sort`](#sort) | `sheet` `reverse` `ascending` `descending` | mekkoxy | `sheet` |
| [`axisTitles`](#axistitles) | `{x?, y?}` | scatter, bubble | none |
| [`sizeLegend`](#sizelegend) | boolean or caption | bubble | off |
| [`labelContent`](#labelcontent) | `percent` `value` `both` | pie, doughnut | `percent` |
| [`scaleGroup`](#scalegroup) | group name | stacked, clustered, waterfall, line, area, combo | none (own scale) |
| [`shades`](#shades) | array of `{from, to, label?}` | gantt | none |
| [`brackets`](#brackets) | array of `{from, to, label?}` | gantt | none |
| [`today`](#today) | date | gantt | none |

### Numbers

These options apply to every value label, total, arrow label and axis tick of the chart.

#### `unit`

Text added to every value label. A string is a suffix with no space: `"m"` gives `42m`, `"%"` gives
`42%`. For a prefix or a space, use an object: `text` (required), `position` (`"suffix"` by default
or `"prefix"`) and `space` (`false` by default).

```json
{
  "type": "clustered",
  "categories": ["North", "South"],
  "series": [{ "name": "Price", "values": [12.5, 9.8] }],
  "options": { "unit": { "text": "$", "position": "prefix" } }
}
```

That gives `$12.5` and `$9.8`; `{ "text": "€", "space": true }` would give `12.5 €`. With `"%"`,
German and French locales put a non-breaking space before the sign (`42 %`).

#### `decimals`

A fixed number of decimals, 0 to 10. When left out, open-charts uses the fewest decimals (0–2) that
show every value exactly, else enough to show two significant digits of the smallest value (at most
3). Pie and doughnut shares and 100% chart shares default to 0 decimals.

#### `format`

An Excel number format code, which overrides `decimals`. It must contain at least one digit
placeholder (`0`, `#` or `?`). Supported: up to three sections (`positive;negative;zero`), `0 # ?`
placeholders, `,` for thousands grouping, a trailing `,` to divide by 1,000, `%` (multiplies by
100), quoted text, `\x` escapes and `_x` spaces. Colour codes such as `[Red]` and `*` fill codes are
ignored. The locale decides the decimal mark and grouping character.

```json
{
  "type": "waterfall",
  "categories": ["Start", "Gain", "Loss", "End"],
  "series": [{ "name": "Cash", "values": [1250, 320, -480, "e"] }],
  "options": { "format": "#,##0;(#,##0)" }
}
```

Negative values then read `(480)`. In stacked and Mekko charts, setting a `format` turns off the
rounding that makes segment labels add up exactly to the column total.

#### `locale`

Decimal mark, thousands grouping and percent spacing:

| Locale | Example |
|---|---|
| `en-US` (default) | 1,234,567.5 |
| `en-GB` | 1,234,567.5 |
| `en-IN` | 12,34,567.5 |
| `de-DE` | 1.234.567,5 |
| `fr-FR` | 1 234 567,5 |

A language alone (`"de"`) or another region (`"de-AT"`) matches the first locale of that language.
Negative numbers use a true minus sign (−). In Gantt charts, `en-US` writes milestone dates month
first; any other locale writes them day first.

#### `scale`

Divides every value by a thousand, million or billion and puts `k`, `m` or `bn` right after the
number. `"auto"` picks the largest magnitude below the largest value. The whole chart shares one
magnitude, so all labels match.

```json
{
  "type": "stacked",
  "categories": ["2023", "2024"],
  "series": [{ "name": "Revenue", "values": [1250000, 1730000] }],
  "options": { "scale": "auto", "unit": { "text": "$", "position": "prefix" } }
}
```

Labels read `$1.25m` and `$1.73m`.

### Layout and axes

#### `orientation`

`"horizontal"` draws stacked, clustered and 100% charts as bars from the left, with categories down
the side. Other types reject it. Horizontal charts name their series in a legend.

#### `valueAxis`

Shows a value axis with tick labels. Off by default for column, waterfall, combo, area and Mekko
charts, because the values are labelled on the chart. **Line charts show the axis by default**; set
`"valueAxis": false` to hide it. On a Mekko XY chart the baseline also becomes an axis for the
cumulative widths. Scatter and bubble charts always have both axes; pie, doughnut, Harvey, table and
Gantt have none.

#### `zeroBased`

Line, scatter and bubble charts start the value axis at zero unless all values are positive and sit
in a narrow band (the spread is less than 40% of the largest value), in which case the axis fits the
data. `true` forces zero in; `false` always fits the data.

#### `gap`

Space between columns as a fraction of the column width: `0` makes columns touch, `0.5` (the
default) leaves half a column between them. From 0 to 10, in the editor too.

#### `scaleGroup`

Charts on one slide with the same `scaleGroup` name share one value scale: a value unit is equally
long in all of them, so a 7 in one chart is a seventh as tall as a 49 in the other. The group takes the
smallest scale among its charts — the chart with the largest values for its size keeps its own
scale, the others leave room above their columns. Charts of different sizes still compare
correctly, because the scale is points per unit, not the axis range. Read by stacked, clustered,
waterfall, line, area and combination charts; names only matter within one slide. In PowerPoint,
Update chart, Apply in the editor and resizing a chart re-lay out the rest of its group too (the
add-in finds them by the `OC_SGROUP` tag). See [Several charts on a slide](#several-charts-on-a-slide)
for an example.

### Labels and legend

#### `seriesLabels`

How series are identified: `"right"` writes each series name next to its last segment, line or
band; `"legend"` draws a legend above the chart; `"none"` leaves them out.

| Chart type | Default | Notes |
|---|---|---|
| stacked, percent, line, area, area100, mekko, combo (stacked) | `right` | Mekko switches to a legend when its last column is too narrow, unless you set the option. |
| clustered, combo (clustered), any horizontal chart | `legend` | `right` is drawn as a legend in horizontal charts. |
| waterfall | no names with one series | With several series the default `right` becomes a legend; `legend` also works with one series. |
| pie, doughnut | `right` | `right` puts the category names outside the slices; `legend` lists them; `none` hides them. |
| scatter, bubble | `legend` with several series, `none` with one | `right` is treated like the default. |
| mekkoxy | `right`; `none` with a single height series | |
| gantt | milestone key when there are two or more milestone series | `none` hides the key. |
| harvey, table | not used | Row names are always shown. |

#### `labelContent`

Pie and doughnut slice labels: `"percent"` (shares, the default; rounded so they add up to exactly
100%), `"value"` (the values, with the chart's number options) or `"both"` (the example below reads `118m (57%)`).

```json
{
  "type": "pie",
  "categories": ["Enterprise", "Mid-market", "SMB"],
  "series": [{ "name": "Revenue 2025", "values": [118, 60, 29] }],
  "options": { "labelContent": "both", "unit": "m" }
}
```

### Decorations

#### `totals`

A bold total label above each column. On by default for `stacked`, `mekko` and `mekkoxy` (with two
or more height series; with one, its value always sits on top); off by default for the others.
`percent` and `combo` (stacked columns only) show the column totals of the raw values, `area` puts
them above the top band (not `area100`), and `doughnut` shows the grand total in the hole. Other
types reject it.

#### `cagr`

A compound annual growth arrow between two categories of a `stacked` or `percent` chart, computed
from the column totals. `from` and `to` are category indices counted from 0, and `to` must come
after `from`. Both totals must be positive.

The number of years is taken from, in order:

1. `years`, if given (a positive number);
2. dates read from the two category labels (`"2021"`, `"FY24"`, `"Q1 2023"`, `"Jan 2024"` …; see
   [Dates](#dates)), on a 30/360 day count;
3. the distance between the two indices.

```json
{
  "type": "stacked",
  "categories": ["2021", "2022", "2023", "2024", "2025E"],
  "series": [
    { "name": "Enterprise", "values": [42, 58, 75, 96, 118] },
    { "name": "SMB", "values": [18, 21, 22, 26, 29] }
  ],
  "options": { "unit": "m", "cagr": { "from": 0, "to": 4 } }
}
```

The arrow reads `+25.1%` (totals 60 → 147 over four years, read from the labels 2021 and 2025E). Set `"cagr": null` to remove it.

#### `difference`

An arrow between the totals of two categories of a `stacked` or `percent` chart, labelled with the
signed difference. Same `from` / `to` rules as `cagr`.

```json
{
  "type": "stacked",
  "categories": ["Q1", "Q2", "Q3", "Q4"],
  "series": [
    { "name": "Licences", "values": [120, 126, 131, 140] },
    { "name": "Services", "values": [24, 25, 27, 30] }
  ],
  "options": { "unit": "m", "difference": { "from": 0, "to": 3 } }
}
```

#### `totalsAt`

Waterfall: the category indices drawn as total columns standing on the baseline. See
[Waterfall](#waterfall) for the default.

```json
{
  "type": "waterfall",
  "categories": ["EBITDA 2024", "Volume", "Price", "Operating EBITDA", "FX", "EBITDA 2025"],
  "series": [{ "name": "EBITDA", "values": [100, 18, -17, null, -6, null] }],
  "options": { "unit": "m", "totalsAt": [0, 3, 5] }
}
```

### Type-specific options

#### `step`

Line charts only: draws each line as steps, horizontal to the next category and then vertical.

#### `percentData`

100% charts only: the datasheet already holds percentages, so each column keeps its own total (a
column that adds up to 85% stays short of the top) instead of being scaled to 100%.

```json
{
  "type": "percent",
  "categories": ["Survey A", "Survey B"],
  "series": [
    { "name": "Yes", "values": [52, 61] },
    { "name": "No", "values": [33, 25] }
  ],
  "options": { "percentData": true, "valueAxis": true }
}
```

#### `combo`

Combination charts only: draw the column series `"stacked"` (default) or `"clustered"`. Mark the
line series with `"as": "line"`; every series shares one value axis.

```json
{
  "type": "combo",
  "categories": ["2022", "2023", "2024"],
  "series": [
    { "name": "Product", "values": [40, 52, 61] },
    { "name": "Services", "values": [12, 15, 19] },
    { "name": "Plan", "values": [50, 60, 72], "as": "line" }
  ],
  "options": { "unit": "m", "totals": true }
}
```

#### `mekko`

Mekko charts: `"percent"` (default) stacks every column to 100% and labels segments with shares;
`"unit"` keeps absolute segment heights and labels values. Column widths always encode the column
totals.

```json
{
  "type": "mekko",
  "categories": ["Enterprise", "Mid-market", "SMB"],
  "series": [
    { "name": "Us", "values": [120, 40, 15] },
    { "name": "Competitor A", "values": [80, 60, 30] },
    { "name": "Others", "values": [50, 45, 60] }
  ],
  "options": { "unit": "m" }
}
```

#### `sort`

Mekko XY only: column order from left to right — `"sheet"` (datasheet order, default),
`"reverse"`, `"ascending"` or `"descending"` by column height.

#### `axisTitles`

Scatter and bubble only: `{ "x": "…", "y": "…" }`, either may be left out.

#### `sizeLegend`

Bubble only: `true` adds a size legend (one bubble of a round size, top right); a string also adds
that caption, e.g. `"Revenue ($m)"`.

#### `shades`

Gantt only: shaded periods (holidays, freezes) behind every row, each `{ "from", "to", "label"? }`.
`to` must come after `from`. A label hangs from a bracket under the chart.

#### `brackets`

Gantt only: brackets under the rows marking periods such as phases, each `{ "from", "to", "label"? }`.

#### `today`

Gantt only: a red line through every row at this date, labelled "Today". It is never read from the
clock, so the chart does not change by itself. A date outside the chart's range is reported and not
drawn.

```json
{
  "type": "gantt",
  "categories": ["Design", "Build", "Test"],
  "series": [
    { "name": "Start", "values": ["Jan 2026", "Mar 2026", "Jun 2026"] },
    { "name": "End", "values": ["Mar 2026", "Jun 2026", "Aug 2026"] }
  ],
  "options": {
    "shades": [{ "from": "2026-07-27", "to": "2026-08-17", "label": "Summer break" }],
    "brackets": [{ "from": "2026-01-01", "to": "2026-06-01", "label": "Phase 1" }],
    "today": "2026-04-13"
  }
}
```

## Style

`style` sits on the deck, on a chart (over the deck's style, for that chart only) or, inside a
`.pptx`, on a chart's stored spec, and changes fonts, colours and number defaults. Every key is
optional.

| Key | Type | Default |
|---|---|---|
| `font` | font name | `Arial` |
| `fontSize` | points, 4–72 | `12` |
| `text` | colour, labels | `tx1` (the theme's text colour) |
| `muted` | colour, secondary text | `595959` |
| `axis` | colour, axes, connectors, arrows | `7F7F7F` |
| `background` | colour, separators drawn in the background colour | `bg1` (the theme's background) |
| `palette` | non-empty array of colours, one per series (or slice) in turn | `accent1` … `accent6` |
| `positive` | colour, waterfall increases | `3E8E5E` |
| `negative` | colour, waterfall decreases | `C0504D` |
| `theme` | object: hex colour per theme slot (`accent1`…`accent6`, `dk1`, `lt1`, `dk2`, `lt2`) | the open-charts theme |
| `numbers` | object: `locale`, `decimals`, `scale` for every chart | none |

### Colours and the presentation's theme

A colour is a hex colour (`"1F3A5F"` or `"#1F3A5F"`) or a **theme colour**: `accent1` … `accent6`,
`dk1`, `lt1`, `dk2`, `lt2`, or `tx1`, `bg1`, `tx2`, `bg2` (text and background as the slide master
maps them, so text stays readable on a dark-background master). Series colours (`series[].color`)
may be theme colours too.

A theme colour follows the presentation the chart is in: the `.pptx` stores it as a theme colour
(`schemeClr`), and the add-in sets it as one, so Design › Variants or a new template recolours the
chart like PowerPoint's own shapes. The default style uses the six accents for series, `tx1` for
text and `bg1` for separators, so a chart inserted in a client's deck takes the deck's colours.

`theme` says what the theme colours stand for where there is no presentation to ask: the preview,
the theme of decks the command line writes, and the choice of black or white for labels on a
coloured fill. Its default, the open-charts theme, is a navy-to-grey ramp (`1F3A5F 3E6A9E 7FA3CC
B9CDE5 A6A6A6 D9D9D9`, text `222222`). In PowerPoint the add-in uses the slide's own theme colours
instead, so label contrast always matches what is drawn.

```json
{
  "style": {
    "palette": ["accent1", "accent2", "B9CDE5"],
    "theme": { "accent1": "0B5394", "accent2": "6FA8DC" },
    "numbers": { "locale": "de-DE", "decimals": 1 }
  },
  "slides": [
    {
      "title": "Mix by channel",
      "chart": {
        "type": "percent",
        "categories": ["2023", "2024"],
        "series": [
          { "name": "Online", "values": [45, 58] },
          { "name": "Stores", "values": [55, 42] },
          { "name": "Partners", "values": [12, 14], "color": "accent4" }
        ]
      }
    }
  ]
}
```

### Number defaults

`numbers` sets `locale`, `decimals` and `scale` for every chart in the deck, with the same values as
the [options](#numbers) of those names. A chart's own options win, and a default only applies to
chart types that read that option.

Labels on a dark fill switch to white automatically. Text is measured with Arial metrics (or the
metric-compatible Liberation Sans) unless you pass other fonts to the command line with `--font`.

## Validation and errors

Every spec is validated before layout. Each problem is reported with a JSON Pointer to the exact
place, for example:

```
/series/1/values/3: must be a number or null, got string "n/a"
/options/cagr/to: "to" must come after "from"
/options/step: not used by stacked charts (only line)
```

The rules beyond the types listed above:

- every series has exactly one value per category, and series names are unique;
- `cagr`, `difference` and `totalsAt` indices are within the categories;
- every option only on the chart types the options table lists for it (`null` for `cagr` or
  `difference` is accepted anywhere: it means none);
- `decimals` and `gap` within 0–10;
- Gantt: at least a Start and an End series, both dates or neither for each activity, end after start;
- Mekko XY: at least two series; widths not negative.

The command line stops on an invalid spec; the editor marks the offending cell in red.

Layout problems are different: the spec is valid, but a label does not fit. The chart is still
drawn, the label is hidden, and the reason is reported (`hidden: SMB / 2021: segment too small`).
The command line prints these to stderr; `--strict` turns them into a failing exit code.

## Dates

Category labels (for CAGR) and Gantt cells are read as dates when they look like one:

| Form | Examples | Read as |
|---|---|---|
| Year | `2024`, `FY24`, `CY2024`, `2025E`, `'24` | 1 January |
| Quarter | `Q1 2023`, `Q1 FY24`, `2023 Q1`, `2023-Q1`, `1Q23` | first day of the quarter |
| Half | `H1 2023`, `2H23` | 1 January or 1 July |
| Month | `Jan 2023`, `January 2023`, `Mar-24`, `2023-01`, `01/2023` | first day of the month |
| Day | `2023-01-15` | that day |

Suffixes such as `E`, `A`, `F`, `P`, `B`, `est.`, `act.` and `fcst.` are ignored, and two-digit years
below 70 are 20xx. Gantt `shades`, `brackets` and `today` accept the same forms.

## How charts stay editable

Each chart is written as one PowerPoint group of ordinary shapes, with tags (contract version 1):
`OC_V` (contract version), `OC_ENGINE` (engine version), `OC_SPEC` (this JSON; split into
`OC_SPEC_0…n` plus `OC_SPEC_N` if it is very long), `OC_FRAME` (the chart's box in points) and
`OC_FONT`. `open-charts import deck.pptx` turns those tags back into a deck JSON.
